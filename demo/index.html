A clean TypeScript port of e-means — Meta FAIR's mini-batch replacement for k-means — validated against the real faiss implementation. Runs in Node, the browser, and edge runtimes where faiss can't.

Watch e-means win the race

18,396 word embeddings — the (nearly) full vocabulary of Shakespeare's complete works — clustered live in your browser. Same data, same number of clusters, same starting point — scrub the slider or hit play to watch e-means finish while k-means is still working.

The numbers

e-means (5 epochs) vs. this package's own Lloyd's k-means (up to 25 epochs), same k-means++ initialization, on the 18,396-word / 50-dimension Shakespeare embeddings used in the demo above. k-means uses its full epoch budget here and still doesn't beat e-means's loss.

3.7–4.6× faster wall-clock
5 epochs needed (vs. 25)
≤ 0.3% loss difference vs. k-means

Full methodology and additional benchmarks are in the README. These numbers are honest: we don't claim to match faiss's CUTLASS/GPU wall-clock speed, only the algorithmic win — reaching the same loss in far fewer passes over the data.

Works with your stack

e-means has no framework dependencies — it takes Float32Array vectors in and returns cluster assignments out. Here's how that looks with the tools people most often pair with embeddings. 

import { fit } from 'e-means'

const embeddings = await embedAllChunks(chunks) // however you already embed
const flat = new Float32Array(embeddings.flat())
const { labels, centroids } = fit(flat, embeddingDim, k)

export default {
  async fetch(request: Request): Promise<Response> {
    const { vectors, k } = await request.json()
    const { fit } = await import('e-means')
    const flat = new Float32Array(vectors.flat())
    const { labels } = fit(flat, vectors[0].length, k)
    return Response.json({ labels: Array.from(labels) })
  },
}
